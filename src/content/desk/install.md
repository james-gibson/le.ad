# Installing the desk

A desk you have to find in a tab is a worse desk. le.ad ships a `manifest.json` at the root of
the site and a service worker generated at build time, so the page installs as its own window
and opens when the network does not.

## The manifest

```json
{
  "id": "/le.ad/",
  "name": "le.ad — an empty hot desk",
  "short_name": "le.ad",
  "start_url": "./",
  "scope": "./",
  "display": "standalone",
  "background_color": "#2E4A5F",
  "theme_color": "#2E4A5F",
  "icons": [
    { "src": "icons/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "icons/icon-512.png", "sizes": "512x512", "type": "image/png" },
    { "src": "icons/maskable-512.png", "sizes": "512x512", "type": "image/png", "purpose": "maskable" }
  ]
}
```

Four of those fields are the ones installability actually needs, and each is there for a
reason rather than for a checklist:

- `id` fixes the identity of the installed app. Without it the identity is inferred from the
  start URL, and moving the start URL makes the browser treat the install as a different app.
- `start_url` and `scope` are relative, so the same file works from `/le.ad/` on Pages and
  from `/` in development.
- `background_color` is the wall, not white. The installed window paints it before the first
  frame, and a white flash on a steelblue desk is a visible seam.
- `theme_color` is the same steelblue, so the title bar of the installed window does not sit
  on the page like a second surface.

The icons are generated by `scripts/icons.mjs` — drawn, not exported from a design tool. The
mark is the lamp on a desk, at 192, 512, and a maskable 512 with the glyph inside the safe
circle so a launcher can crop it to any shape.

## The worker

`sw.js` is written by `scripts/postbuild.mjs` after Vite finishes, because a precache list has
to name the hashed assets that were just built. It does three things:

1. precaches the app shell, the icons, the manifest and the fonts;
2. serves navigations network-first, falling back to the cached shell — a deep link still
   starts the app offline;
3. clears caches whose version does not match the build, so a deploy cannot leave a reader on
   an old renderer.

The version is the build's commit. There is no cache name to edit by hand, and the publish
guard checks that the worker names the bundle that actually shipped.

## What install does not do

- It does not move the desk's state to the cloud. The row is still in `localStorage` and the
  claim link.
- It does not claim a desk. Installing the desk and claiming a desk are different acts, and
  conflating them would make the lease depend on a browser prompt.
- It does not pretend to work in a browser that has not offered a prompt. Firefox on desktop,
  and any browser on a first visit, get the honest alternative: open the browser menu, or add
  the page to a home screen.

To check it yourself: open the site in Chrome or Edge, use the address-bar install control,
and then turn the network off. The row is still there, the lamps still work, and the only
thing you lose is a claim you had not yet copied.
